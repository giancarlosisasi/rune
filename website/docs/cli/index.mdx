# Commands

```
rune <command> [options]

Commands:
  run <name> [args...]      Run a script by name
  list                      List all available scripts
  inspect <name>            Show how a script resolves and where it comes from
  init                      Write a starter config
  cache clear               Remove every cached config result

Options:
  -h, --help                Print help
  -V, --version             Print version
```

## Streams

The rule is about what is being written, not about which command is writing it. A command whose
product is text writes that text to standard output. Everything Rune says about itself — warnings,
diagnostics, failures — goes to standard error, on every platform. A command that spawns a child
gives standard output to the child.

`rune list` and `rune inspect` are the two whose product is text, so both write their report to
standard output. `rune run` hands the stream to the script, which is why
`rune run build > artifact.txt` captures the build's bytes and nothing of Rune's. `rune init` writes
a file, and reports the path it wrote on standard error.

A failed query is a diagnostic, not a product. `rune inspect nope` writes its message to standard
error and leaves standard output empty, so a pipeline reading the report never receives a complaint
in its place.

## Colour

Rune's own messages are plain text. The one place it uses colour is the prefix in front of a
parallel group's output, and `NO_COLOR` set to any value turns that off. See
[Prefixed output](/reference/output).

## Environment variables

Rune reads `npm_config_script_shell`, `NO_COLOR`, `FORCE_COLOR` and `CI`, and sets three `RUNE_`
variables for every script it runs. See [Environment variables](/reference/environment-variables).
