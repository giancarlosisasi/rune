# Installation

Rune installs as a development dependency at the root of the repository. The package resolves one
native binary for the current platform through optional dependencies, so nothing is compiled and
no postinstall script runs.

<PackageManagerTabs command={{
  npm: 'npm install --save-dev @gio-labs/rune',
  yarn: 'yarn add -D @gio-labs/rune',
  pnpm: 'pnpm add -D @gio-labs/rune',
  bun: 'bun add -d @gio-labs/rune',
}} />

Install it once, at the workspace root. Packages call the binary through `node_modules/.bin`,
which every package manager links for the whole workspace.

## Verifying the install

<PackageManagerTabs command={{
  npm: 'npx rune --version',
  yarn: 'yarn rune --version',
  pnpm: 'pnpm rune --version',
  bun: 'bun rune --version',
}} />

The version printed here is the version of the native binary, not the wrapper package. They are
released together and always match.

## The first config

`rune init` writes `rune.config.ts` into the directory it is run from, with a comment header naming
every field the version that wrote it accepts. It refuses to overwrite an existing file. Run it at
the repository root.

<PackageManagerTabs command={{
  npm: 'npx rune init',
  yarn: 'yarn rune init',
  pnpm: 'pnpm rune init',
  bun: 'bun rune init',
}} />

The result, under the comment header:

```ts title="rune.config.ts"
export default {
  scripts: {
    hello: {
      command: "echo rune is set up",
      description: "Check that rune can run a script",
    },
  },
};
```

`rune list` and `rune run hello` both work immediately. [rune init](/cli/init) shows the full file.

Rune finds the config by walking up from wherever it is invoked, so a run from `packages/api/src`
uses the same config as a run from the root.

Adding `import { defineConfig } from '@gio-labs/rune'` and wrapping the object gives you editor
autocomplete. Rune supplies that module itself, so it works with nothing installed.

## Node version

The wrapper is written in conservative JavaScript and declares no `engines` field, so it installs
on any Node version. Node 20.19 and later is the tested floor.

## Platforms

| Platform | Architecture |
| --- | --- |
| Windows | x64, and arm64 through emulation |
| macOS | x64, arm64 |
| Linux | x64, arm64, statically linked against musl |

One static Linux binary per architecture runs on every distribution, glibc and musl alike. The
full table is on [Platforms](/reference/platforms).
